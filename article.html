Arhitectura unui blog modern: de la zero la producție pe 1 GB RAM

Cum construim un blog performant, sigur și cu design modern cu Django + Wagtail CMS, Nginx și PostgreSQL — fără a depăși 512 MB RAM în producție.

A
Admin
24 Feb 2026 · 8 min citire · 142 vizualizări
🏗️

Când vine vorba de a construi un blog sau o platformă de publicare de conținut în 2026, suntem bombardați cu opțiuni: WordPress, Ghost, Next.js + headless CMS, Hugo, Jekyll... Fiecare are avantajele și dezavantajele ei. Dar ce faci când ai un buget limitat și un server cu 2 CPU și 1 GB RAM?

În acest articol îți voi prezenta arhitectura pe care am ales-o pentru Ursoaia EDU — un stack complet, modern, performant și care se încadrează confortabil în limitele unui VPS de categorie mică.

De ce nu WordPress

WordPress este soluția implicită pentru mulți, și există motive bune pentru asta. Are o comunitate uriașă, mii de plugin-uri și teme, și este foarte ușor de folosit. Dar are un cost:

  • PHP + MySQL + Apache/Nginx + cache plugin = complicat de configurat corect
  • Securitate: actualizări constante, vulnerabilități frecvente în plugin-uri
  • Performanță slabă fără cache agresiv (WP Super Cache, Redis, etc.)
  • Design datat — necesită teme premium sau dezvoltare custom
"Cel mai bun tool este cel pe care îl cunoști — dar dacă înveți ceva nou, asigură-te că merită investiția."

Stack-ul ales: Django + Wagtail

Am ales Django ca framework backend și Wagtail CMS ca sistem de gestionare a conținutului. Iată de ce:

1. Wagtail CMS

Wagtail este unul dintre cele mai bune CMS open-source disponibile în 2026. Construit pe Django, are o interfață de administrare modernă, sistem flexibil de tipuri de pagini (page models), editor rich-text și suport nativ pentru imagini și media.

2. Consum redus de resurse

Un server Gunicorn cu 2-3 workers rulând o aplicație Django + Wagtail consumă în jur de 150-250 MB RAM — lăsând suficient spațiu pentru PostgreSQL (~100 MB) și Nginx (~20 MB).

3. Securitate

Django are securitate solidă din cutie: protecție CSRF, prevenire SQL injection prin ORM, XSS protection, click-jacking protection. Înregistrarea închisă (invite-only) se implementează simplu prin customizarea modelului de utilizator.

Arhitectura sistemului

┌──────────────────────────────────────────────────────┐
│                     Internet                          │
└─────────────────────┬────────────────────────────────┘
                      │ HTTPS (port 443)
┌─────────────────────▼────────────────────────────────┐
│                    Nginx                              │
│          (reverse proxy + static files + SSL)         │
│                  Certbot / Let's Encrypt              │
└──────────┬───────────────────────────────────────────┘
           │ HTTP (intern, port 8000)
┌──────────▼───────────────────────────────────────────┐
│              Gunicorn (WSGI server)                   │
│              2-3 workers × Django app                 │
│              Wagtail CMS (admin panel)                │
└──────────┬───────────────────────────────────────────┘
           │
┌──────────▼───────────────────────────────────────────┐
│              PostgreSQL 16                            │
│              (baza de date principală)                │
└──────────────────────────────────────────────────────┘

Deploy: Docker Compose pe Ubuntu 22.04 LTS
SSL:    Let's Encrypt (auto-renewal)
RAM:    ~350-450 MB total în producție

Structura proiectului Django

blog/
├── blog/               # Django project settings
│   ├── settings/
│   │   ├── base.py
│   │   ├── production.py
│   │   └── development.py
│   ├── urls.py
│   └── wsgi.py
├── home/               # Wagtail home app
├── blog_posts/         # App pentru articole
│   ├── models.py       # BlogPage, BlogIndexPage
│   ├── templates/
│   └── migrations/
├── users/              # App custom utilizatori
│   ├── models.py       # CustomUser (invite-only)
│   └── views.py
├── static/             # CSS, JS, imagini
├── templates/          # Template-uri globale
├── media/              # Fișiere uploadate
├── docker-compose.yml
├── Dockerfile
├── nginx.conf
└── requirements.txt

Tema dark/light

Tema se implementează cu CSS custom properties (variabile CSS) la nivel de :root și [data-theme="dark"]. JavaScript salvează preferința în localStorage și respectă prefers-color-scheme al sistemului de operare. Zero JavaScript frameworks necesar.

Concluzie

Django + Wagtail este, în opinia mea, cel mai bun compromis pentru un blog modern în 2026: performant, sigur, cu o admin panel frumoasă și un consum de resurse redus. Nu e cel mai simplu de instalat inițial, dar odată configurat, este o plăcere de folosit.

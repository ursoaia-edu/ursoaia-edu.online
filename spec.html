Platformă Blog

1. Obiective & Cerințe

Platforma trebuie să funcționeze ca un blog / site de știri modern, similar cu Medium.com, cu următoarele cerințe de bază:

Cerință Detalii Prioritate
Blog / News site Publicare articole cu rich-text, imagini, video embed, categorii, tags, autor Critică
Design modern Temă dark/light, tipografie curată, responsive (mobile-first), fluid animations Critică
Admin panel Interfață de administrare intuitivă pentru creare/editare/publicare articole Critică
Înregistrare închisă Accesul la admin doar prin invitație sau activare manuală de superuser Critică
Performanță TTFB < 200ms, First Contentful Paint < 1.5s, Lighthouse score > 90 Critică
Consum redus resurse Funcționare stabilă pe 2 CPU, 1 GB RAM, 30 GB SSD Critică
Comentarii Sistem simplu de comentarii (fără cont sau cu cont) sau integrare Disqus Medie
Căutare Căutare full-text în titlu și conținut articole (PostgreSQL FTS) Medie
RSS Feed Feed RSS/Atom pentru abonament la articole noi Scăzută
Newsletter Integrare opțională Mailchimp / Listmonk pentru notificări Scăzută

2. Stack Tehnologic

Am evaluat mai multe opțiuni și am ales Django + Wagtail CMS ca soluție optimă pentru balanța dintre flexibilitate, performanță și consum redus de resurse.

De ce NU alte opțiuni:

  • WordPress — securitate slabă, performanță necesită cache complex, design datat
  • Ghost CMS — Node.js, consum RAM mai mare (~300-400 MB), customizare limitată
  • Next.js + Strapi — Strapi singur consumă 400-600 MB RAM; nu se încadrează în 1 GB total
  • Hugo/Jekyll (static) — nu are admin panel, editare conținut dificilă

4. Schema Bazei de Date

Modelele principale Django/Wagtail. Wagtail extinde sistemul de pagini Django cu un model Page de bază.

CustomUser (AbstractUser)
├── id             UUID PK
├── username       VARCHAR(150) UNIQUE
├── email          VARCHAR(254) UNIQUE
├── is_active      BOOLEAN (false by default — invite system)
├── invite_token   UUID NULL
├── date_joined    TIMESTAMP
└── bio            TEXT NULL

BlogIndexPage (Wagtail Page)
├── [moștenire din wagtail.Page]
├── intro_text     RichTextField
└── [parent: RootPage]

BlogPost (Wagtail Page)
├── [moștenire din wagtail.Page — include: title, slug, date]
├── subtitle       CharField(500)
├── body           StreamField  ← rich blocks: text, image, code, embed
├── cover_image    ForeignKey → Image (Wagtail)
├── author         ForeignKey → CustomUser
├── excerpt        TextField(500)
├── reading_time   PositiveSmallInt (calculat auto)
├── is_featured    BooleanField
├── claps          PositiveIntegerField
└── [many-to-many → Tag]

Tag
├── id             INTEGER PK
├── name           VARCHAR(100) UNIQUE
└── slug           SlugField UNIQUE

Comment
├── id             UUID PK
├── post           ForeignKey → BlogPost
├── author_name    VARCHAR(100)
├── author_email   EmailField
├── body           TextField
├── is_approved    BooleanField (default: false)
├── created_at     TIMESTAMP
└── parent         ForeignKey(self, null=True) ← replies

5. Securitate

5.1 Înregistrare închisă (invite-only)

Modelul CustomUser are câmpul is_active = False implicit. Un nou utilizator poate fi creat doar în două moduri:

  1. Superuser activează manual din panoul de administrare Wagtail
  2. Link de invitație — superuser generează un invite_token UUID unic; utilizatorul accesează /register/<token>/ și completează formularul de înregistrare

Înregistrarea publică la /register/ nu există.

5.2 Configurări Django obligatorii în producție

SECURE_HSTS_SECONDS = 31536000
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
X_FRAME_OPTIONS = 'DENY'
SECURE_CONTENT_TYPE_NOSNIFF = True
SECURE_BROWSER_XSS_FILTER = True
DEBUG = False
ALLOWED_HOSTS = ['ursoaia-edu.online', 'www.ursoaia-edu.online']

5.3 Nginx rate limiting

limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
limit_req_zone $binary_remote_addr zone=api:10m rate=30r/m;

location /admin/login/ {
    limit_req zone=login burst=3 nodelay;
}

5.4 Alte măsuri

  • Backup automat zilnic al bazei de date (pg_dump) — retenție 7 zile
  • fail2ban pentru protecție brute-force SSH și Nginx
  • Utilizator de sistem non-root pentru procesele Docker
  • Secretele (DB password, Django SECRET_KEY) în fișier .env — nu în repository
  • Dependențe Python actualizate regulat (pip-audit)

6. Strategie de Performanță

Pe 1 GB RAM, caching-ul corect este esențial. Abordare în trei nivele:

Nivelul 1: Cache Django (per-view)

# settings/production.py
CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
        # sau Redis dacă RAM permite
    }
}

# În view:
@cache_page(60 * 15)  # 15 minute cache
def blog_index(request): ...

Nivelul 2: Nginx static file caching

location /static/ {
    alias /app/staticfiles/;
    expires 30d;
    add_header Cache-Control "public, immutable";
}

location /media/ {
    alias /app/media/;
    expires 7d;
}

Nivelul 3: Optimizări PostgreSQL

# postgresql.conf (tuning pentru 1 GB RAM)
shared_buffers = 256MB
work_mem = 4MB
maintenance_work_mem = 64MB
effective_cache_size = 768MB
max_connections = 20

Nivelul 4: Frontend

  • CSS custom properties — zero JavaScript framework, theme switch nativ
  • Font Awesome prin CDN cu loading="lazy" pentru imagini
  • CSS și JS minificate în producție (django-compressor sau whitenoise)
  • prefers-color-scheme media query — temă setată înainte de render (no FOUC)

8. Docker Compose & Deployment

# docker-compose.yml
version: '3.9'

services:
  db:
    image: postgres:16-alpine
    restart: unless-stopped
    volumes:
      - postgres_data:/var/lib/postgresql/data
    env_file: .env
    environment:
      POSTGRES_DB: ${DB_NAME}
      POSTGRES_USER: ${DB_USER}
      POSTGRES_PASSWORD: ${DB_PASSWORD}

  web:
    build: .
    restart: unless-stopped
    command: >
      sh -c "python manage.py migrate &&
             python manage.py collectstatic --no-input &&
             gunicorn config.wsgi:application
               --bind 0.0.0.0:8000
               --workers 3
               --timeout 120"
    volumes:
      - static_volume:/app/staticfiles
      - media_volume:/app/media
    env_file: .env
    depends_on: [db]

  nginx:
    image: nginx:1.24-alpine
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/conf.d/default.conf
      - static_volume:/app/staticfiles:ro
      - media_volume:/app/media:ro
      - certbot_conf:/etc/letsencrypt:ro
    depends_on: [web]

  certbot:
    image: certbot/certbot
    volumes:
      - certbot_conf:/etc/letsencrypt
      - certbot_www:/var/www/certbot
    entrypoint: >
      /bin/sh -c "trap exit TERM;
        while :; do
          certbot renew;
          sleep 12h & wait $${!};
        done;"

volumes:
  postgres_data:
  static_volume:
  media_volume:
  certbot_conf:
  certbot_www:

Comenzi de deployment:

# Prima instalare pe VPS:
git clone https://github.com/ursoaia-edu/blog.git
cd blog
cp .env.example .env
# editează .env cu secretele tale
docker compose up -d --build
docker compose exec web python manage.py createsuperuser

# Update:
git pull origin main
docker compose up -d --build --no-deps web
docker compose exec web python manage.py migrate

9. Plan de Dezvoltare

Faza 1 — Săptămânile 1-2
Infrastructură & Setup de bază

Inițializare proiect Django + Wagtail, configurare Docker Compose, setup PostgreSQL, deploy pe VPS, configurare SSL Let's Encrypt, model CustomUser cu sistem invite, template base.html cu dark/light theme.

Faza 2 — Săptămânile 3-4
Modele de conținut & Admin

Modele Wagtail: BlogIndexPage, BlogPost cu StreamField (text, imagine, cod, video embed), sistem Tags, câmp reading_time calculat automat, pagini de categorie, paginare articole.

Faza 3 — Săptămânile 5-6
Frontend & Design

Templates Django cu design Medium-like: pagina principală (feed), pagina articol, sidebar cu trending, topicuri, responsive mobile, animații CSS, dark/light theme complet, optimizare Lighthouse score.

Faza 4 — Săptămânile 7-8
Features avansate

Căutare full-text PostgreSQL, RSS/Atom feed, sistem comentarii cu aprobare moderator, clap/like sistem, pagina profil autor, sitemap.xml, meta tags Open Graph pentru social sharing.

Faza 5 — Ongoing
Monitoring & Optimizare

Integrare Sentry pentru error tracking, backup automat PostgreSQL, monitoring uptime, optimizare query-uri N+1 cu django-debug-toolbar, documentare pentru autori, ghid de contribuție.
